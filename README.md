# 研途奖励册

这是一个无须注册、无须构建的中文本地 Web 应用，把四个月考研奖励计划、每日核心任务、娱乐额度和作息记录放在同一本账里。过程预算为 1,800 美元，考试完成奖和目标奖各 100 美元，总预算 2,000 美元。

## 在 Windows 启动和停止

1. 双击应用目录里的 `start.bat`。
2. 浏览器会打开 `http://localhost:8765`。如果没有自动打开，请手动输入这个地址。
3. 使用时保持启动窗口开启。按 `Ctrl+C` 或关闭启动窗口即可停止；网页数据不会因此删除。

如果双击后窗口立刻关闭，可在应用目录打开 PowerShell，运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\start-app.ps1"
```

只启动而不打开浏览器时，加上 `-NoBrowser`。默认端口 8765 被其他程序占用时，启动器会明确提示；可以先关闭占用程序，也可以临时运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\start-app.ps1" -Port 8877
```

此时地址改为 `http://localhost:8877`。注意：端口也是浏览器存储来源的一部分，换端口后会看到另一份 localStorage；要带回 8765 的记录，请先在原地址导出 JSON，再在新地址导入。

## 每天怎么用

1. 在“今日打卡”填写学习时长、任务完成率、错题复盘、运动、诚信和备注；作息分由作息记录自动提供。
2. 填写三项“今日核心任务”。已完成任务必须写下可核对的成果。
3. 至少完成一项核心任务后，预计分低于 80 解锁 30 分钟，达到 80 解锁 60 分钟，达到 90 解锁 90 分钟；没有完成核心任务时为 0 分钟，即 **0/30/60/90** 四档。
4. iPhone 和安卓共用“一个额度”的含义是：选定这个网页作为手动总账，在任一设备娱乐都计入同一天额度；它不代表设备间自动同步。点击“开始娱乐/暂停娱乐”记录网页计时，其他设备上的使用时间需如实补入这本账。
5. 晚上补录入睡时间，第二天补录起床时间。历史日期也能回填；系统会按该日保存的设置快照重算作息分和周预估。

娱乐会话保存开始、结束时间戳，不靠页面每秒加一来记账。只要仍在同一浏览器和同一地址，刷新或暂时切到后台后会按真实经过时间恢复、结算。额度到截止时间后过期，活动会话会按该日的截止时间自动收尾。

默认时间为：22:15 提醒、22:30 娱乐截止、23:00 入睡目标、次日 07:00 起床目标。当天尚无娱乐会话时，修改设置立即生效；当天已经产生娱乐会话时，新设置排到次日生效，避免事后改变当天规则。

## 奖励、补救池和图表

- 每日 100 分：学习时长 25 分、任务完成率 30 分、错题复盘 15 分、规律作息 10 分、运动 10 分、诚信 10 分。
- 周平均分按 100% / 90% / 75% / 50% / 0% 兑现；少于 5 天打卡还会按覆盖率折算。
- 未兑现部分进入当前阶段补救池。同阶段后续一周平均至少 90 分且打卡至少 6 天，可以按规则释放一部分补救奖励。
- 四阶段预算依次为 300、450、550、500 美元。考试完成奖 100 美元、目标奖 100 美元；页面会显示累计奖励、补救池和预算剩余提醒。
- “历史与统计”可按日期、阶段、分数与守约状态筛选，并查看学习得分、娱乐用时和作息趋势图。

## 数据保存在哪里

数据保存在当前浏览器、当前网址来源的 `localStorage` 中，只写本应用自己的存储键。没有云端账号或服务器数据库：Chrome、Edge、Safari 等不同浏览器各有一份数据，电脑、iPhone、安卓等不同设备也各有一份数据。清除站点数据、重装浏览器或更换端口都可能让当前页面看不到原记录。

第一次打开会生成 13 天完整示例，便于查看奖励池、娱乐和作息图表：

- “清空示例数据”只在系统确认当前仍是完整、未混入个人记录的示例时出现；确认后删除示例并建立空白计划。
- “清空全部本地数据”会删除本应用的学习、任务、奖励、娱乐会话、作息和设置，恢复为空白计划。它不会清理其他网站数据，但此操作不可撤销。

开始正式记录前，建议先清空示例，再设置计划开始日期。

## 备份、导入和旧历史

建议每周导出一次 JSON，并把文件复制到可靠的备份位置。**JSON 是完整恢复文件**，包含学习记录、三项任务、额度、娱乐会话、作息、设置、奖励状态和日志；**CSV 只用于表格分析**，不能完整恢复应用。

导入旧 JSON 的安全步骤：

1. 先导出当前 JSON 备份。
2. 选择旧的版本 1 或版本 2 JSON。系统会先深度校验并显示版本及各类记录数量。
3. 只有再次确认后，导入数据才会整体替换本应用当前数据；这不是逐条自动合并。
4. 替换后，旧学习记录会直接进入本网页的历史列表、奖励计算和统计图表，任务、娱乐与作息记录也会一起恢复。

如果 JSON 无效、损坏或取消确认，当前 localStorage 不会被覆盖。看到“无法导入”时，保留当前页面，换用另一份备份重试；不要先清空现有数据。

## 手机配合与第一阶段边界

当前启动器只绑定电脑的回环地址（loopback / `127.0.0.1`）。手机不能通过电脑的 `http://localhost:8765` 访问：手机里的 localhost 指手机自己。本版本没有经过安全评估的局域网监听模式，所以 README 不提供绕过回环绑定的命令。若未来增加局域网服务，必须同时限制可信网络、检查 Windows 防火墙并理解同网设备可访问数据的隐私风险。

本应用不会自动在 iPhone、安卓和电脑之间同步。需要换设备时，在来源设备导出完整 JSON，再在目标设备导入；导入仍是整体替换。

浏览器也不能读取、识别其他应用的实际使用时间，也不能锁定或强制关闭其他应用（包括游戏、小说或短视频应用）。第一阶段的网页计时器是统一的手动账本，可这样配合系统工具：

- iPhone：在“设置 → 屏幕使用时间”中为游戏、阅读和短视频分类设置“App 限额”，并设置“停用时间”从 22:30 开始。
- 安卓：在“设置 → 数字健康（或数字健康与家长控制）”中设置应用计时器和就寝模式，22:15 提醒，22:30 进入限制时段。

系统工具负责设备侧提醒或限制，网页负责当天 0/30/60/90 分钟额度、跨应用合计和如实记录；两者不会自动交换数据。

## 常见问题

- **端口被占用：** 若已是研途奖励册，启动器会提示直接打开；若是其他程序，会报错而不是假装启动成功。关闭占用程序或用 `-Port 8877`，并留意不同端口的数据相互独立。
- **PowerShell 禁止脚本：** 使用上面的 `powershell.exe -ExecutionPolicy Bypass -File ".\start-app.ps1"`，它只对这一次启动放宽策略，不修改系统全局策略。
- **浏览器数据被清除：** 从最近一次 JSON 备份恢复。没有 JSON 备份时，本地应用无法从云端找回，因为它没有上传数据。
- **刷新后数字变化：** 活动会话按保存的时间戳和当前时间重新计算，这是为了避免后台标签页停摆导致少记；截止后的额度不会因刷新恢复。
- **历史没有“自动合并”：** JSON 导入是整份替换。要保留两份来源，请先分别备份，再选择一份作为主账手工补录另一份的重要记录。
